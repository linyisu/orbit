# orbit-gui

[项目总览](../../README.md)

Orbit 原生桌面客户端，使用 GPUI Kit Component，外观面板使用 GPUI Component Shell。会话执行与数据库由工作区服务负责，GUI 通过 `orbit-client` 接入；账号设置复用 `orbit-auth` 与 `orbit-config`。

## 启动

目前支持本仓库的 Linux 执行环境。先按照根目录说明准备 Rust stable、musl 工具链和模型配置。Ubuntu 24.04 的 GUI 构建依赖：

```sh
sudo apt install build-essential clang pkg-config libfontconfig-dev libwayland-dev \
  libxkbcommon-x11-dev libx11-xcb-dev libssl-dev libzstd-dev libasound2-dev libvulkan-dev
cargo run -p orbit-gui --locked -- --config config.toml
```

GUI 和 CLI/TUI 一样内嵌静态工作区服务。已有兼容服务时，构建可用 `ORBIT_WORKSPACE_SERVER=/absolute/path/to/orbit-workspace-server` 复用它；运行时也可用 `--server` 覆盖连接的服务程序。GUI 暂未加入便携打包，默认 Shell 目录仍从源码目录加载。

```sh
cargo run -p orbit-gui --locked -- \
  --config /path/to/config.toml \
  --workspace /path/to/project \
  --model provider::model \
  --resume SESSION_ID
```

`--model`、`--resume` 可省略：新会话优先使用上次选择的模型，再回退到可用模型；恢复会话使用服务保存的模型。认证沿用现有认证目录，也可指定 `--auth-dir`。`--database` 与其他客户端含义一致。

## 界面与操作

GUI 与 TUI 的对应入口见 [功能对照](../../FRONTEND_PARITY.md)。输入历史使用 Ctrl+Up／Ctrl+Down，返回最新位置时恢复未发送文字与选区；有图片草稿时不会切换历史。Ctrl+W 关闭当前标签，Ctrl+. 停止当前响应，均可在快捷键设置中改绑。普通剪贴板文件插入文字引用，现存本地图片路径（含引号、多路径及 `file://`）可转为附件。`/plan` 进入计划模式，`/plan view` 审阅计划，`/build` 返回执行模式，裸 `/resume` 打开会话选择器。

- 没有全局底部状态栏。上下文与当前模型额度属于输入区，执行状态位于输入框上方，点击可进入工作面板。
- 设置是窗口级的独立页面，使用原生 Sidebar、搜索和表单。默认进入全局设置：外观、账号、快捷键对所有项目生效，MCP 与高级 Agent 配置供新建会话使用；技能与插件属于工作区资源，会话记忆属于当前会话，各页明确显示作用域。普通页面只有一层滚动，插件目录使用完整正文视口。跟随系统／浅色／深色、文字大小、字体、对话宽度与侧栏宽度保存到 GUI 偏好文件。账号页先列连接，点击添加后再选择登录方式或填写 API 表单。
- 恢复历史会连续读取已有分页，不等待实时轮询间隔；读取期间仅显示恢复状态，不把历史工具数量当成正在运行的进度。折叠工具内容在展开时解析 Markdown。

- 左侧列出当前主机上所有有会话的目录，展开目录选择会话；使用 Kit Tree 提供虚拟列表和方向键导航，Enter 打开会话。跨目录恢复会同步切换工作目录，保留当前窗口内的文字和附件草稿。
- 侧栏按“置顶”和“项目”显示完整项目树。项目行的省略号与右键菜单提供项目置顶和上移／下移；拖动项目图标到另一项目行可调整顺序，拖入另一分区会采用该分区的置顶状态。项目排序和置顶按连接与数据库保存，切换标签、刷新目录和重启后保留；旧的会话置顶会在读取目录后迁移为所属项目置顶。会话行仍可重命名、自定义分类和删除，分类保留在项目内部；删除会话不会清除项目的顺序或置顶。删除需确认，运行中的会话不可删除。
- “打开项目…”或 Ctrl+O 使用当前环境：本地调用系统目录选择器，SSH / WSL 直接浏览当前目标机器的目录，无需再次填写连接信息；选中目录保留主机、用户、端口及服务配置，取消不改变当前会话。标题栏项目菜单保留“打开本地项目…”作为显式切回本地的入口。侧栏直接提供“连接远程项目…”及环境选择菜单；SSH 配置别名、用户、端口、私钥及 WSL 发行版／用户均有原生输入。远程工作区和数据库路径由目标机器解析，本机配置与私钥由本机读取。连接时显示部署阶段，可取消、修改连接与重试；后台 SSH 验证留在所属任务，切回后继续。远程目录列表仅属于当前连接主机。
- 项目移动或重命名后，打开新目录会按与 TUI 相同的目录身份找回历史。若从侧栏打开的旧目录已不存在，会提示选择迁移后的目录，先通过服务端重新关联原项目，再恢复原会话；跨文件系统移动或复制后删除旧目录也适用。取消保留当前会话和草稿；目标目录已有其他项目的会话时会拒绝合并。普通打开目录不会自动重新关联项目。
- 工作区操作错误进入通知与详情入口；初次连接失败直接显示完整错误和重试／修改操作。已取消或失败的远程标签再次提交相同连接信息会重新连接，关闭最后一个失败标签会回到本地。空会话隐藏不适用的变更、计划操作。
- 输入区模型菜单先列供应商／连接及模型数量，第二层只显示该连接下的模型名称；当前连接与当前模型都有勾选标记，提交时保留完整连接标识。
- 对话右侧提供按用户提问分轮的圆点定位栏：圆点、轮次和回到最新按钮整体垂直居中，点击跳转、悬停预览，实心点跟随正文当前轮次；长会话的圆点列表可独立滚动。聚焦定位栏后，↑/↓ 切换轮次，Home 到首轮，End 回到最新。
- 项目侧栏、任务标签、对话、可收起的工作面板。新任务和已有任务的输入框都固定在底部。正文和输入框默认保持相同宽度，并与任务区两侧留有间距，设置中可切换居中窄栏；侧栏与工作面板可拖动调整。
- 同时打开多个任务，切换只改变可见视图，后台运行、输入草稿、附件、滚动位置和面板选择继续保留。关闭当前标签后优先激活左侧最近的可见标签，左侧没有标签时才选择右侧；关闭后台标签不改变当前标签。标签显示运行、待处理和未读状态；运行中可关闭标签视图，任务继续运行并可从侧栏重新打开；停止需要显式操作。未确认发送及附件仍保存恢复快照，后台失败会重新显示待处理标签。
- 打开已有会话时复用当前完全空白的“新会话”标签；目标已在其他标签打开时移除空白占位并切到目标。有文字、图片、正在处理的附件、待发送内容或未保存文件与设置表单的标签继续保留，普通切换标签与启动恢复不触发替换。
- 重启后恢复打开的任务、标签顺序、当前标签和各任务的未发送文字、图片附件。没有发送过的新任务恢复为草稿，不尝试加载不存在的服务端会话。显式指定 `--workspace` 或 `--resume` 时仍打开指定目标。粘贴图片保留独立副本；普通附件引用原文件路径。
- 任务与草稿保存在 `$XDG_STATE_HOME/orbit/gui-tasks.json`（默认 `~/.local/state/orbit/gui-tasks.json`），图片副本位于旁边的 `gui-tasks.assets`。指定 `--preferences /path/gui.json` 时使用 `/path/gui.tasks.json` 与 `/path/gui.tasks.assets`。单个后台写入器原子替换快照，正常退出等待最后一次保存；保存失败会显示通知。服务程序、配置或数据库覆盖参数不同的启动不会恢复其他数据源的任务。
- 已打开的工作区断线后，按 1、2、4、8、16 秒间隔最多重连五次；输入区显示重连状态，失败后可手动重连并查看错误。重连恢复会话记录和执行状态，保留等待期间继续编辑的草稿，不自动重发消息、审批或命令。未确认的普通发送保留请求 ID，显式重试仍使用同一凭据；运行中补充输入须自行确认服务是否已接收。初次打开项目失败直接显示错误，不循环重试。
- 工作面板按执行、计划、变更、Agent 组织：工具详情来自事件记录；计划沿用服务端版本与审批；变更页区分 Orbit 检查点和 Git 暂存状态；子 Agent 从服务端目录发现，可查看持续更新的执行记录、定向发送消息或停止所选轮次。
- 执行页以实际命令或文件名为主标题，集中显示状态、目录与耗时，可筛选全部、进行中和失败记录。打开执行页后可用 ↑／↓、Home／End 定位，Enter 查看完整输出；切换筛选会清除旧选择。悬停提示限宽限行，输入队列入口固定在面板底部。计划按步骤排列，变更行分别提供差异和编辑入口，Agent 行显示实际委派任务摘要、角色和状态。
- 后台任务错误保留在所属任务，标签提示待处理，不在其他任务中弹出错误通知。返回该任务后可通过输入区打开详情。
- 原生 Markdown、代码、表格、行内与独立公式；公式按实际笔画范围裁边，保留文本基线。`MessageScroller` 管理虚拟列表、滚动和回到最新消息，工具与思考记录按需展开。
- Markdown 代码块与 TUI 共用 `orbit-syntax` 语法包和语言别名，包含 Verilog、SystemVerilog 等；高亮随深浅色主题切换，未知语言保留纯文本。编辑器继续使用 Kit 的增量 Tree-sitter 高亮。
- 表格按实际文字测量列宽并适应当前内容区：短列限制在内容宽度内，长说明与命令在单元格内换行；窄窗口和字体放大时允许列宽继续收缩，所有列保持可见，不使用横向滚动条。对话、工作面板报告和计划预览使用同一排版规则。
- 选择、粘贴、拖入和预览图片、移除附件；消息图片通过服务读取，支持远程工作区。多行输入、模型、推理强度、执行/计划与审批模式切换、发送、停止及运行中补充文字。收到服务确认后才清空已发送的草稿；普通发送失败可用相同请求 ID 重试。
- 工具审批使用 Dialog 展示完整操作证据，可允许一次、记住并允许或拒绝；计划审批使用独立表单。Agent 问答自动显示在输入区：编号选项、自由回复、跳过与发送；多题逐题作答，上一题与设置往返保留填写内容，收起后可重新展开。Enter 提交当前题，Shift+Enter 换行；失败保留答案供重试。关闭窗口只断开客户端，不取消服务端任务。
- 打开会话后自动请求额度，每 60 秒再查询一次；输入区显示当前模型所属额度池的两个额度条与重置倒计时，点击打开详情，可手动刷新。摘要复用 TUI 的共享额度选择逻辑；详情只显示账号共享额度，不列出单模型计数。Antigravity 的 Gemini 与 Claude / GPT 分别展示周、5h 窗口，没有共享额度数据时明确显示缺失，不用单模型计数代替。更新时间每秒重绘，刷新失败保留上次结果。
- 明暗主题、文字大小、对话宽度与侧栏宽度保存在 `$XDG_CONFIG_HOME/orbit/gui.json`，未设置 XDG 时使用 `~/.config/orbit/gui.json`。可用 `--preferences` 指定独立文件。

`Ctrl+Shift+P` 打开可搜索的命令面板。以下操作直接调用现有客户端协议：

| 功能 | 入口 |
| --- | --- |
| 本地、SSH、WSL 项目 | 侧栏「打开项目」「连接远程项目」及环境菜单，或 `--ssh HOST` / `--wsl DISTRO`；SSH 密码和确认使用原生弹窗 |
| 文件浏览、编辑、差异及撤销 | 命令面板「打开文件」「文件变更」及工作面板文件行；原生文件树、编辑器和差异页；`/file path`、`/diff path`、`/undo path` 可直接定位 |
| 计划、Agent 提问、审批 | 工作面板「计划」、输入框上方的待办入口及命令面板 |
| 旁路提问、继续提问、停止、历史 | 命令面板及 `/btw 问题`；原生列表选择记录，继续所选线程，回答增量更新；停止等待服务确认 |
| 子 Agent 列表、后续消息与停止 | 工作面板「Agent」及命令面板；列表显示真实状态和独立工作树，按行选择，无需填写 ID；停止等待所选轮次终态 |
| 待处理输入与命令输出 | 运行中发送的文字在输入框上方显示真实暂存状态，可逐条编辑或撤回；`/queue`、管理入口或工作面板打开完整分页队列；执行中的工具行打开可暂停、选择与复制的原生 stdout / stderr 查看器 |
| 项目任务、状态、依赖与释放认领 | 侧栏「项目任务」、窗口项目菜单及命令面板；在任务页搜索、选择、新建和编辑，无需填写任务 ID |
| 记忆添加、搜索与停用 | 设置中的「记忆」及命令面板 |
| 技能加载、刷新，MCP，插件来源与启停 | 设置中的独立技能、MCP 工具、插件市场页面及输入区命令搜索 |
| 上下文、压缩、状态、诊断 | 命令面板与输入区；压缩时显示实际阶段 |
| 会话重命名、删除、历史、压缩记录、存储；项目关联 | 会话行右键或 F2 / Delete、命令面板；操作绑定所选会话 |
| OAuth 与 API 连接 | 「账号与模型连接」；支持 Antigravity、ChatGPT、Gemini、Claude，以及 OpenAI Chat/Responses、Anthropic Messages API；保存后执行「刷新模型」 |

在输入框键入 `/`，命令补全列表会出现在输入框上方，继续输入即可筛选，方向键选择、Enter 确认、Esc 收起。列表和全局命令面板共用同一分发入口，支持中文名称及英文关键词搜索。

命令后的参数也在同一个列表中补全：模型连接与模型、技能、推理强度、工作模式、审批模式、任务和记忆子命令。`/cd` 的目录、`/diff` 与 `/undo` 的文件、`/resume` 的会话以及任务／记忆编号从当前工作区读取；远程工作区不会读取桌面本机的目录。Tab 或单击填入候选，有后续参数时继续提示；完整参数填入后 Enter 执行。目录以 Tab 继续展开，Enter 使用已补全的目录。Esc 收起后，迟到的响应不会重新打开列表。

输入框也支持 `/usage`、`/changes`、`/diff`、`/status`、`/context`、`/compact`、`/skills`、`/mcp`、`/diagnostics`、`/plan`、`/plugins`、`/tasks`、`/memory`、`/btw`、`/queue` 等已有入口。未知命令显示本地错误，不发送给模型。

“设置 → 技能 → 从来源导入…”支持 GitHub `owner/repo`、HTTPS / SSH Git 地址、GitHub `tree` 子目录或 `blob` 技能文件链接、本地目录及 `SKILL.md`。扫描会获取来源并列出可用技能，勾选后将完整技能目录（含脚本、参考资料和资源文件）安装到项目的 `.orbit/skills`，随后刷新列表。同名技能标出冲突，不覆盖已有内容。相对路径、`~/` 和 Git 获取均由当前工作区主机解析，远程项目使用远程主机的网络和文件；SSH 使用该主机已有的密钥或 agent 与主机信任记录。GitHub 含斜线分支名需在链接中编码为 `%2F`。

插件市场兼容在市场条目中直接声明能力、没有独立 `plugin.json` 的包（例如 Anthropic skills）。共享仓库根目录的包只加载各自列出的技能，详情中的数量与启用后的技能目录一致；已有缓存无需删除或重新下载。

导入采用一次扫描、预览、选择安装的流程，不持续同步来源；扫描预览有效期为 15 分钟，安装失败或失去确认后需要重新扫描核对。来源获取限时 60 秒；项目正在运行任务时需先等待该轮结束。该流程参考 [vercel-labs/skills 的来源解析、发现与安装实现](https://github.com/vercel-labs/skills)，由 Orbit 的工作区服务执行，不在桌面另建安装后端。

在“设置 → 快捷键”搜索命令或按键，可编辑、录制最多三步的组合键、清除绑定、恢复单项或全部默认。修改立即应用于所有工作区并保存到 GUI 偏好文件；冲突需显式替换，保存失败保留编辑并提供重试。发送和换行只影响消息输入框，标准文本编辑、文件保存及弹窗导航仍由对应原生控件提供。以下列出默认键位：

手工填写的未知按键、与其它命令或原生编辑操作冲突的已存键位，不阻止启动：对应命令临时使用默认键，设置页显示原始配置与修复入口，直到用户编辑或恢复默认才更新该项。

| 操作 | 默认快捷键 |
| --- | --- |
| 发送 | Enter |
| 换行 | Shift+Enter |
| 新会话 | Ctrl+N |
| 下一个／上一个已打开任务 | Ctrl+Tab / Ctrl+Shift+Tab |
| 展开／收起工作面板 | Ctrl+Shift+E |
| 聚焦输入框 | Ctrl+L |
| 展开／收起侧栏 | Ctrl+B |
| 设置 | Ctrl+, |
| 命令面板 | Ctrl+Shift+P |
| 文件变更 | Ctrl+Shift+D |
| 搜索会话 | Ctrl+P |
| 关闭弹窗 | Esc |

OAuth 使用本机浏览器和回调端口；未提供手动回调地址输入。GUI 不包含 CLI 的打包、后台服务进程管理等维护命令。真实 OAuth 登录、SSH/WSL 连接需要在对应环境验收，隔离测试不替代这些验证。

本轮已用仅监听本机回环地址的独立 SSH 主机验收真实 v23 服务：公钥握手、静态服务上传校验、目标目录列表、进入带空格的子目录、通过原生连接表单打开新工作区、设置内读取和加载目标技能、连接日志查看及复制。测试使用临时密钥、配置、数据库与服务安装路径，不访问用户的 SSH 配置，不调用模型；默认主目录缓存自动部署、WSL 和真实 OAuth 登录仍需对应环境验收。

## GUI 功能与验收

对照 [GPUI Kit 的 Ghostex 应用页](https://gpui-kit.com/apps/ghostex/)和 [Gupi 应用页](https://gpui-kit.com/apps/gupi/)，桌面工作流需要把项目、会话、工具活动与资源设置连接起来。Ghostex 展示多 Agent 会话、可读差异、后台任务和远程机器；Gupi 展示项目会话、历史分支、临时任务及应用内资源。下表记录 Orbit 自身的功能路径与验收要求，不把参考应用的截图当作 Orbit 已实现功能。

## 运行与界面的边界

```text
Workbench（窗口与任务选择）
  └─ Workspace × N（一个任务一个长期 Entity）
       ├─ Backend（独立连接、事件游标、轮询与取消）
       │    └─ orbit-client → 工作区服务 → Agent / 工具 / 审批 / 存储
       ├─ Execution（只读事件投影：阶段、工具、修改记录、子 Agent）
       ├─ Conversation（消息 Entity 与滚动状态）
       └─ 输入草稿、附件、计划、问题、工作面板
```

`WorkspaceEvent` 表达打开、激活、全局页面导航和状态变更意图。Workbench 持有统一标题栏、标签滚动视口、全局页面、项目侧栏及任务 Entity，不通过重建会话实现切换；项目目录列表只在相同主机、配置与数据源之间共享。会话 ID 相同但连接到不同 SSH/WSL 主机或数据库的任务不能相互替代。迁移后的新目录仍经过服务验证。

服务继续拥有执行、持久化、计划版本和权限决策，GUI 不另建 Agent 循环或数据库。`Execution` 消费协议事件：工具开始不代表文件已修改，父任务结束不代表后台子任务结束，压缩也不是等待模型回复。历史重放使用同一投影；新的用户轮次清空该轮工具列表，保留会话修改和委派记录。

设计研究参考了 [Gupi 的会话宿主与界面边界](https://github.com/suxiaoshao/gupi)、[Ghostex 的会话工作区](https://github.com/maddada/Ghostex)、[Farcaster 的运行控制](https://github.com/behzade/farcaster)、[Wake 的历史目录组织](https://github.com/iAmCorey/Wake)、[Vibex 的运行与 UI 边界](https://github.com/vibex-ai/vibex)，以及 [T3 Code 的 orchestration v2 设计文档](https://github.com/pingdotgg/t3code/tree/main/docs/orchestration-v2)。后者是目标架构文档；Wake 主要用于历史浏览。这里借鉴职责和信息组织，未复制这些项目的界面代码、品牌或素材。

## GPUI Kit 与 Shell 约定

实现遵循 `gpui-kit`、`gpui-kit-design-guides` skills，以及所依赖 GPUI Kit 的 AGENTS.md、Coding Guides 和 Design Guides：

- `gpui_kit::init` + `gpui_kit::open_window` 负责宿主与 overlay；不另建 Root。
- Button、Tree、TabBar、Textarea、Attachment、Message、MessageScroller、Progress、Dialog、Sheet 和 Resizable 均复用 Component。
- 输入、消息和滚动状态由长期存在的 Entity 持有；任务和订阅跟随窗口。流式事件只更新对应消息的文本状态。
- 布局采用 rem 与组件尺寸，颜色来自主题 token。原生窗口边界和用户选择的字体字号使用像素，其余布局使用 rem。
- Tokio 处理连接与文件读取，通过有界事件队列回到 GPUI。额度使用独立连接，避免阻塞消息轮询与取消。
- `Theme::change` 同步 Component 与 Base/Shell；偏好文件由一个后台写入者串行、原子替换。

默认 Shell 在 [appearance/main.js](appearance/main.js)，也可指定 `--appearance /path/to/directory`。调试构建会监听脚本变化；运行时生成的 `gpui-kit.d.ts` 与模块声明不提交。Host Module `orbit-appearance` 只暴露主题读写，不向脚本开放模型凭据、文件系统或工具执行能力。

明暗配色集中在 [appearance/theme.json](appearance/theme.json)，由宿主加载到 Component 主题，Shell 外观面板与原生控件共享相同 token。

GPUI Kit、Shell 和 Component Shell 锁定到同一提交 `1ccf011`。Shell 依赖它的 rquickjs 兼容层，因此 workspace 包含相应 patch；LLRT 的 RSA/PKCS1 预发布依赖采用该版本 Kit 的兼容锁定组合。Kit 和 Orbit 的 tree-sitter 都带 native `links`，workspace 统一为 0.26.13，仓库解析回归需一起验证。构建请保留 `--locked`。

`vendor/gpui-pre-wgpu` 保留 0.3.8 的字体渲染源码与许可证，仅修复按 ASCII `m` 错误移除合法 emoji／符号字体的判断。字体选择预览和显式字形回退均可触发原问题；应用通过 Base Root 的字体回退接口统一覆盖正文、控件与代码，具体字体列表属于 Orbit 主题。

独立原生 UI 验收可运行：

cargo run -p orbit-gui --locked -- \
  --server "$PWD/target/debug/orbit-gui-fixture" \
  --config /tmp/orbit-gui-fixture.toml --auth-dir /tmp/orbit-gui-fixture-auth \
  --database /tmp/orbit-gui-fixture.db \

  --preferences /tmp/orbit-gui-preview.json

发送 `fail` 会失败一次，重试成功；`approve` 出现审批入口，`question` 出现 Agent 表单，`math` 展示公式。`workbench` 模拟约十秒的工具执行、委派和文件修改，可在执行期间 Ctrl+N 新建任务、输入草稿，再用 Ctrl+Tab 返回检查原任务继续运行，随后验证工作面板的计划审阅、文件差异、子 Agent 查看与发消息。

`font-fallback` 展示中文、emoji 标题、加粗、行内代码、代码块、肤色、ZWJ 组合和旗帜；切到不含中文字形的界面／代码字体后检查回退，遍历 emoji 字体预览后再检查正文，复制仍须保留原始文本。

在 fixture 工作区放入 `preview.png` 后恢复 `demo`，比较聊天图片和输入框中粘贴图片的预览：应使用同一比例和窗口边界；点击缩略图删除按钮只移除附件。在运行中的场景粘贴 PNG，图文应保留为草稿，响应结束后通过包含图片的正常请求发送，不应成为丢失图片的文本补充。

`disclosures` 展示五次工具调用，首尾包含 50／30 行输出；提示第一行保持 `disclosures`，后面可追加长用户消息。展开首项、末项及思考记录，标题和正文开头应直接可见；阅读区按实际聊天高度扩展，滚到首尾也不应带动主聊天。工作区下 `.fixture-disclosure-hold` 文件会暂停第二次调用，删除后继续追加，可验证阅读位置不被运行中的新记录打断；`disclosures-live` 另提供短暂延迟。

`disclosure-flow` 验证执行记录的自动展开与收起。发送前在工作区创建 `.fixture-disclosure-flow-text`、`.fixture-disclosure-flow-stream`、`.fixture-disclosure-flow-resume` 和 `.fixture-disclosure-flow-final` 四个文件：首先应自动显示已完成的工具和思考标题，空正文增量不会收起；展开思考可检查多段英文、连续长标识符及中文的边界和换行。依次删除 `-text`（首段正文开始，应自动收起；紧随其后的 `FLOW-LATE-REASONING` 思考增量不能隐藏答复或重新展开记录）、手动重新展开、删除 `-stream`（正文继续，手动展开应保留）、删除 `-resume`（重新执行工具，应自动展开）、删除 `-final`（最终正文开始，应再次收起）。各阶段由标记文件控制，不依赖操作速度；完成后重新恢复会话，历史执行记录应默认收起。
