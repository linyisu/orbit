# Orbit 限制审计

审计日期：2026-09-17。范围覆盖工具、沙箱、模型传输、执行循环、上下文、存储和 TUI。以下数值来自本仓库实现；“后续处理”是建议，不代表已实现。MiB / KiB 均为二进制单位。

## 本次已修复

实际会话 run 9 的命令正文为 **9502 UTF-8 字节**，被 `run_command` 的 8192 字节校验拒绝，并非 API 限制。该校验已移除。命令通过项目外的私有临时脚本执行，避免只是把工具上限调大后又撞上操作系统单个 argv 参数的限制。

原先 stdout 或 stderr 超过 32 KiB 会触发杀进程，正常构建也可能因此中断。现改成持续排空输出、分别保留末尾 32 KiB、报告总字节数和截断标志。只因超时或取消才主动中断；命令自己的退出码保留。被截掉的前文目前仍会丢弃。

验证包括：通过工具审批入口提交超过 8 KiB 的命令；在只读和可写两种真实 Bubblewrap 沙箱中执行约 240 KB 的命令；100 KB 输出后仍返回最终标记和退出码 7；无限输出仍能按超时结束；中文输出边界不切出无效的 UTF-8 半个字符。

## 工具与执行环境

| 位置 | 当前约束 | 影响与后续处理 |
| --- | --- | --- |
| `run_command.rs` | 命令文本无独立长度上限；不得为空或包含 NUL | 已取消任意 8 KiB 门槛。请求本身仍占用模型上下文和内存，不能把这称为无限容量。 |
| `sandbox.rs` 输出 | stdout、stderr 各返回末尾 32 KiB | 已与执行生命周期分离。后续应将完整输出存到用户数据目录并提供分页回读、过期清理和磁盘配额，不在用户项目内落日志。 |
| `run_command.rs` 超时 | 默认 120 秒，最大 600 秒；可用 `[command]` 配置 | 已可调。真正长任务需要后台执行、状态查询和取消能力，不能仅不断调大阻塞超时。 |
| `sandbox.rs` 快照 | 64 MiB、10000 个遍历条目、64 层目录 | 大仓库会在执行前失败。启动前准备副本不计入进程超时；复制中检查取消，但阻塞文件 I/O 不保证即时退出。需要按项目规模配置、准备阶段预算，最终减少每次全量复制。 |
| `sandbox.rs` 工作目录 | 可写 `/workspace` 共 128 MiB，包含源码和构建产物；`/tmp` 64 MiB | 明显不适合普通大型构建；应由明确的资源配置管理，并考虑磁盘后端，不能简单换成很大的 tmpfs 占用内存。 |
| `sandbox.rs` 进程资源 | 单文件 64 MiB、地址空间 4 GiB、文件描述符 1024、NPROC 1024；执行受墙钟超时和取消控制 | 地址空间不是实际内存，可能阻碍 V8/JVM 的虚拟地址预留；NPROC 按真实 UID 计数可能受宿主线程影响。取消了近似墙钟超时的 CPU rlimit，避免 I/O 等待导致提前 SIGXCPU；仍需要配置和更准确的总量控制，目前没有 cgroup 聚合预算。 |
| `sandbox.rs` 可用内容 | 排除 `.git`、`target`、`node_modules`、`.venv`、`__pycache__`、符号链接；不保留可执行位 | 现有依赖、Git 操作、直接执行项目脚本会受阻。属于执行环境能力缺口，不能靠加大数字解决。 |
| `sandbox.rs` 生命周期 | 每条命令新副本，修改和产物丢弃，无持久依赖缓存 | 构建和测试必须在同一条命令中；无法正常分步安装、构建、测试。应设计持久隔离工作区与受控修改机制。 |
| `sandbox.rs` 工具链与网络 | 只挂载系统工具目录，不提供宿主 home、用户工具链、网络和凭据 | Rustup/NVM 等用户工具链不可用；YOLO 只改变审批，不解除隔离。后续需要显式工具链和网络授权，不能默认暴露 home/密钥。当前系统级执行实现依赖 Linux。 |
| `read_file.rs` | 全文件最多 1 MiB；默认 200 行、最多 500 行；正文最多 32 KiB | 即使只读几行，也先读取整文件并检查总大小。应流式分页，把文件大小与单次返回量分开。 |
| `read_file.rs` 超长行 | 单行可被 32 KiB 输出预算截断，但行号已推进 | 用下一行继续会漏掉同一行余下内容。应增加字节/字符续读位置或明确的超长行读取路径。 |
| `write_file.rs` / `edit_file.rs` | 原文件、写入内容和编辑结果受 1 MiB 限制 | 大生成文件或大配置会失败；应区分文件处理上限、参数预算、差异预览预算，避免多份完整内容和大 diff 无约束占用内存。 |
| 文件创建 | 父目录必须已经存在；没有持久 mkdir 工具 | 命令创建的目录在副本中被丢弃，因而无法正常创建新的项目目录树。应提供受路径保护的目录创建能力。 |
| `list_files.rs` | 深度默认 1、最大 8；每页默认 200、最大 1000；offset 和扫描最多 20000；返回 32 KiB | 返回分页和遍历上限混在一起，大仓库不能完整翻页。应有独立遍历预算和稳定续读位置；当前每页重新扫描，目录变化可能重复或漏项。 |
| `workspace.rs` | 单目录最多 10000 条目 | 目录枚举先失败，下游分页也无法解决；需要有界迭代。 |
| `list_files.rs` 忽略规则 | 默认隐藏文件关闭，可显式开启；生成目录不递归，可明确指定；不使用 `.gitignore` | 范围策略应可解释和可配置。受保护路径、符号链接检查不应作为“限制过小”直接关闭。 |

## 存储与界面

SQLite 的 3 秒 busy timeout 是锁等待预算，不是数据库容量。256 条事件或 250 ms 的 flush 阈值是批量写入策略，不是事件丢弃上限。会话没有发现小的固定条数上限，但恢复时读入完整事件历史，长会话仍有内存和性能风险，应做分页加载与归档策略。

TUI 输入区最多显示 6 行、标题 80 字符、对话框和预览行数上限主要控制显示，不等于输入/模型内容被截断。审批滚动位置使用 u16，极长预览仍可能无法完整翻阅，需要单独处理。滚轮每次 5 行和 40 ms 门控是此前按体验调整的交互参数，不应与任务容量一起随意放大。

## 主流实现的参考与差异

- [Pi bash](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/tools/bash.ts) 将输出截断与进程执行分开，超出保留量后把完整输出写入临时文件；超时可选。值得借鉴的是日志回读和执行语义，不是简单取消所有资源预算。
- [Pi truncate](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/tools/truncate.ts) 默认返回预算是 2000 行或 50 KiB，并区分头部/尾部截取。[Pi read](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/tools/read.ts) 使用返回分页，但底层仍可全文件读入；不能照搬为流式大文件读取方案。
- [Pi write](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/tools/write.ts) 支持递归创建父目录；这暴露了 Orbit 目前目录创建能力的缺口。
- [Codex unified exec](https://github.com/openai/codex/blob/main/codex-rs/core/src/unified_exec/mod.rs) 分开管理单次返回 token 预算、进程输出缓冲和可继续查询的运行会话；审计时源码包含默认 10000 输出 tokens、1 MiB 缓冲、64 个进程上限。这些单位和用途不同，不能直接拿来替换 Orbit 的每一项字节常量。
- 本地 SztuCode 的 `py-runtime/src/sztu_code/core/tools/builtin/bash.py` 同样限制返回输出但不因输出量杀进程；其 `communicate()` 会先收集输出再截断，也不能作为有界内存实现直接照搬。

以上对照为审计当日源码，链接到上游 main，后续可能变化。
