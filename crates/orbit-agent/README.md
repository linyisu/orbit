# 上下文预算与整理

每次模型请求前检查历史、工具定义与输出预算，工具返回后重新检查。`context_tokens` 表示总额度；模型配置的 `input_context_tokens` 表示独立输入额度，不从它再次扣除最大输出。当前 token 数按序列化字节数和消息开销估算，不是服务端实测 usage。

## 分层整理

TUI、`orbit chat` 与库共用规划器。带会话归档的运行在可用输入额度约 60% 时尝试精简旧工具证据；需要模型摘要的自动整理仍默认在 85% 触发。`/compact` 可提前触发，单个长工具任务也支持。

1. 按完整 assistant/tool 批次选择近期工作区，目标为输入额度的六分之一、最多 32,000 tokens。保留系统指令、最新用户请求与最新完整批次；不能为了达到目标切断工具配对。最后一个批次较大时保留它，并重新校验容量。
2. TUI 和 chat 将原始上下文事务写入中央数据库的独立归档。只有归档成功，才允许精简工具正文和大参数。归档没有向项目写入文件。
3. 先保留旧输出的首尾、部分错误行和原文引用，必要时分三档缩小摘录。全部对话文字和近期批次不变。若已回收到目标附近且至少减少 25%，直接完成，无摘要模型请求。快速路径允许占用到输入额度的约三分之一，避免仅为少量额外空间调用模型。
4. 仍过大时，以已有摘要和新增历史记录生成增量摘要。旧工具证据先使用可回读摘录，大文字字段才拆成带角色、来源、字段名及字节偏移的片段；每次请求仍为合法 JSON。每个成功的摘要批次持久化来源指纹、结构化摘要和记录游标；同一来源的后续尝试从游标继续。
5. 摘要输出上限为可用输入额度的八分之一、默认最多 4,096 tokens；每次摘要输入上限默认估算 16,384 tokens，同时检查实际模型输入预算。实际从最多 4,096 tokens 的批次起步，响应快才逐步放大，超时或输出截断则缩小，避免慢模型在第一批就耗尽时间。自动整理的单次请求和总期限默认分别为 45 秒、180 秒；手动 `/compact` 分别为 180 秒、3,600 秒。手动整理优先生成完整摘要；本地模型返回带说明的有效 JSON 时会提取结构化对象，格式无效时最多再请求一次修复。若仍无法整理，原上下文或已归档原文均不会丢失，已完成批次可供下次继续。各期限可在 `compaction` 配置中分别用 `request_timeout_seconds`、`total_timeout_seconds`、`manual_request_timeout_seconds`、`manual_total_timeout_seconds` 调整。若对话模型较慢，可用 `compaction.model` 指定单独的摘要模型。
6. 手动整理遇到摘要格式仍无效且原文已归档时，使用归档与近期完整消息生成可回读投影，明确标记哪些历史尚未摘要；已完成的部分摘要会保留。超时或上游服务失败仍保留当前上下文。自动整理仅在约 92% 以上启用这条紧急路径，较低用量下失败仍保留原上下文。归档失败、取消或无法满足硬预算时不发布新投影。

摘要仍是有损的模型产物，结构正确不保证语义完整。不能只用压缩率判断任务质量。下一代分层上下文运行时的目标、数据边界及验收标准见 [CONTEXT-RUNTIME.md](../../CONTEXT-RUNTIME.md)。

## 原文回读与审计

`read_history` 是模型工具，使用压缩记录中的 `archive_id`。可通过 `query` 精确文本搜索，或用 `message`、`offset`、`length` 分页读取原始序列化消息；跨消息结果使用 `next_after_message` 翻页。默认每条 2,000 字符，每页至多八条。归档 ID 必须属于当前会话，`/new` 和 `/resume` 会同步切换读取范围。历史是证据，不是新的指令，也不授权重新执行过去动作。

非交互 `chat --disable history` 禁用历史读取与工具精简，保留完整记录的模型摘要路径。直接使用 Agent 库时默认也不精简工具原文；宿主可通过 `with_context_archive` 提供可靠存储，但必须同时提供对应的模型读取工具。

每次整理记录策略 `tool_pruning`、`summary` 或 `archive_projection`，以及估算前后 tokens、摘要请求次数、累计摘要输入估算量、原文引用、来源切点及文件活动。`archive_projection` 明确表示归档投影已发布、模型摘要未完整完成；旧版本的本地模板回退记录仍可审计。

```sh
orbit sessions compactions <会话ID>
```

原文归档在处理之前独立持久化，相同原文在同一会话内复用归档 ID。失败或取消不会删除已成功保存的摘要批次。有效模型上下文仍在整个任务成功结束时提交；逐批进度只对完全相同的来源前缀可续接，不能把未成功任务的压缩审计记录当成已发布的恢复点。紧急投影是明确标记覆盖缺口的临时方案，不等于完成了模型摘要。

新会话的用户消息、模型回复和工具结果另存于只追加的规范消息日志，与执行检查点在同一事务提交。`sessions.history` 目前仍是运行中的模型上下文投影；投影尚未由规范日志重新生成。迁移前的会话标记历史缺口，不会把旧摘要认作完整原文。

文件活动来自成功工具回执，不依赖模型声称已经修改。`read` 表示曾读取，`written` 表示历史写入成功，不保证当前磁盘内容相同。多次压缩通过 `with_file_activity` 和事件恢复累计记录。

TUI 只显示一条整理状态，区分“旧工具输出已精简”“上下文已整理”与失败。`/context` 查看当前估算预算。Agent 已利用服务端 usage 校准估算，并在服务端拒绝超限请求时尝试缩小投影后重发一次；这不保证所有供应商都会返回可用 usage 或可识别的超限错误。

## 测试

```sh
cargo test -p orbit-agent --offline
```

集成测试覆盖完整工具批次、失败保留、单回合手动压缩、原文分页与会话隔离。真实 API 的摘要质量和多次压缩后的任务成功率仍需单独验收；本地回放数据不能代替该验收。

模型返回 `max_tokens` / `length` / `incomplete` 时，Agent 明确报告输出未完成，不执行该条响应的工具，也不自动发送同样预算的回退请求。流式思考可显示，但不会加入普通回答上下文。增加预算能延长输出空间，不保证模型一定完成任务，也不能超过服务端支持的限制。

`max_turns` 默认 `75`、`max_tool_calls` 默认 `500`；设为 `0` 才表示本轮任务不限次数。TUI 和 `orbit chat` 都可用 Ctrl+C 取消。默认 `timeout_seconds = 600`，流式请求按无数据间隔计时，持续收到思考或输出不会因总耗时超过十分钟被截断；非流式请求按总时长计时。

默认量级参考 [Claude Code 的输出和命令配置](https://code.claude.com/docs/en/env-vars)及[默认不限任务轮数](https://code.claude.com/docs/en/cli-reference)。通用上下文默认 128000 并不代表所有模型都支持；模型能力以服务端为准，显式配置优先。例如当前 [DeepSeek Flash](https://api-docs.deepseek.com/quick_start/pricing/) 公布 1M 上下文和最高 384K 输出，可配置 1000000 上下文、64000 输出作为实际工作预算。不会自动根据模型名称套用可能过时的上限。
