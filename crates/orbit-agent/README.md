# 上下文预算与总结

Agent 在每次模型请求之前检查上下文预算，包括工具定义、历史消息和输出预留；工具返回后进入下一次模型请求时重新检查。接近上限时默认尝试自动总结较早历史；压缩后仍超预算时停止本次运行，不会静默截断用户输入或工具结果。

`config.toml` 可设置 `context_tokens = 128000`，省略时默认为 128000，CLI 要求至少 8192。此值是用户配置的总预算，不会自动查询模型的上下文窗口。当前按序列化 JSON 的字节数除以 3，再计入消息开销，进行跨协议近似估算；它不是精确 tokenizer，也不是服务端计费用量。CLI 的 `max_output_tokens` 默认 32000，既作为请求的输出上限，也计入上下文预算预留；必须为正数且小于 `context_tokens`。部分模型的思考也消耗此预算。直接使用 Agent 库且未指定请求输出上限时仍按 4096 tokens 预留。请根据所用模型调整预算并留有余量。

## 自动压缩

默认 `auto_compact = true`，可在配置文件顶层设为 `false` 禁用。流式 TUI、流式 CLI 和非流式执行使用同一机制。

- 每次模型请求前计算可用输入预算 `context_tokens - max_output_tokens`，估算用量达到其 85% 时尝试压缩。
- 优先保留最近两轮用户对话。如果单个任务已经很长，可以总结当前任务较早的完整执行批次，同时原样保留当前用户要求、系统指令和最近工具批次。不在工具调用与对应结果之间切分。
- 选择保留部分时，以输入预算的 60% 减去摘要预留为目标。摘要输出预留为可用输入预算的八分之一，限制在 256–4096 tokens；不改变正常回答的输出上限。
- 总结不提供工具，只把历史作为数据；摘要仍为用户级背景，不能提升成系统指令。过长的历史按 UTF-8 边界分段、累积总结，每次额外请求也检查总预算。摘要可能遗漏信息，尤其多次累计总结后，需要实际验收任务质量。
- 空摘要、含工具调用、明确截断、超过 64 KiB、未缩小上下文或仍超预算的结果均拒绝。早期压缩失败而原上下文仍能放下时继续运行，输入再增长约 10% 可用预算后才重试，避免每次工具调用都请求总结。
- 总结支持取消。无法压缩的超大用户输入、最近工具批次或工具定义仍可能导致预算错误；不会暗中删掉它们，也不会因失败而发送超预算的正常请求。

TUI 显示开始、完成或失败提示，并将其作为事件保存。`/context` 显示开关状态。算法采用本地近似 token 估算，不能保证与服务端 tokenizer 完全一致；目前不根据服务端超限错误自动重试。

设计参考 [Anthropic 的上下文工程说明](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)，这里实现的是跨协议的客户端总结，不依赖供应商专用压缩接口。

## 真实 API 验收

```sh
bash scripts/try-live.sh --context --prepare-only
```

脚本准备独立项目、会话库和权限为 0600 的配置副本，仅测试配置使用 32000 总预算、12000 输出预留以便触发压缩，日常配置不变。运行打印的 `start.sh`，让模型读取 TASK.md。任务先阅读十二份审查资料，再记录关键事实并完成 scheduler 修复；用打印的 `check-evidence.py` 检查早期资料是否保留。该校验和项目原有测试分别验证信息保留与代码修复，不能仅凭出现压缩提示判定成功。准备过程不调用 API。

## TUI 命令

- `/context`：显示已保存上下文的估算用量、输出预留和总预算。尚未发送的输入不计入显示值，提交时会重新检查。
- `/compact`：总结较早对话，保留最近两轮完整用户对话，包括其中的工具调用和结果。至少需要三轮已完成的对话。

真实模式下，总结会发起一次额外模型请求，最多输出 2048 tokens，不提供工具。原系统消息保持不变，总结作为用户级背景资料加入上下文。空摘要、包含工具调用的摘要、明确被截断的摘要、超过 32 KiB 的摘要，以及未能缩小上下文的摘要都会被拒绝。总结请求本身以及压缩后的上下文也必须满足预算；特别长的旧历史或最近两轮可能使压缩失败，需要调高适用预算或用 `/clear` 创建新会话。

压缩成功后，新上下文与运行结果在同一数据库事务中保存，重启恢复时使用它；原始对话事件仍可查看，不会删除。失败或取消时保留上一次成功的上下文。模型摘要可能遗漏细节，完整记录仍是追查依据。自动压缩同样遵守这个持久化规则：只有整个任务成功完成后，新的模型上下文才成为下一轮的恢复点；失败或取消后恢复上一轮成功上下文，已经落盘的执行事件仍保留。

## 无 API 测试

```sh
cargo run -p orbit-cli -- --database /tmp/orbit-context.db tui --demo
```

依次输入三次 `read Cargo.toml`，每次等待完成，然后输入 `/context`、`/compact` 和 `/context`。演示模式生成明确标记的机械提要，仅用于测试预算、压缩、持久化和恢复流程，不代表真实模型的语义总结质量。内容过短、无法缩小时会保留原上下文并提示失败。

退出后可用相同数据库路径执行 `sessions list`，再用 `tui --demo --resume <ID>` 恢复。原始事件和当前上下文可通过 `sessions show <ID>` 检查。

模型返回 `max_tokens` / `length` / `incomplete` 时，Agent 明确报告输出未完成，不执行该条响应的工具，也不自动发送同样预算的回退请求。流式思考可显示，但不会加入普通回答上下文。增加预算能延长输出空间，不保证模型一定完成任务，也不能超过服务端支持的限制。

`max_turns` 和 `max_tool_calls` 默认均为 `0`（本轮任务不限次数），可配置正数设限；TUI 仍可用 Ctrl+C 取消。默认 `timeout_seconds = 600`，流式请求按无数据间隔计时，持续收到思考或输出不会因总耗时超过十分钟被截断；非流式请求按总时长计时。

默认量级参考 [Claude Code 的输出和命令配置](https://code.claude.com/docs/en/env-vars)及[默认不限任务轮数](https://code.claude.com/docs/en/cli-reference)。通用上下文默认 128000 并不代表所有模型都支持；模型能力以服务端为准，显式配置优先。例如当前 [DeepSeek Flash](https://api-docs.deepseek.com/quick_start/pricing/) 公布 1M 上下文和最高 384K 输出，可配置 1000000 上下文、64000 输出作为实际工作预算。不会自动根据模型名称套用可能过时的上限。
