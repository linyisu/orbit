# orbit-agent

[项目总览](../../README.md)

`orbit-agent` 是 Orbit 的核心智能体规划与上下文生命周期管理库。它负责维护多轮对话状态、协调工具调用、估算模型输入预算，并通过分层压缩与归档回读机制，保障长周期工程任务在有限模型上下文窗口内稳定运行。

## 实现入口与代码组织

- [agent.rs](src/agent.rs)：运行循环、取消边界、工具配对、后台完成通知与 journal 刷盘；大段运行回归位于 [agent/tests.rs](src/agent/tests.rs)。
- [context.rs](src/context.rs)、[autocompact.rs](src/autocompact.rs)、[compaction.rs](src/compaction.rs)：输入估算、结构化摘要和整理生命周期。
- [background.rs](src/background.rs)、[inbox.rs](src/inbox.rs)、[checkpoint.rs](src/checkpoint.rs)：任务组、补充消息与持久化接口。子代理宿主及模型选择在 [orbit-service/src/subagents.rs](../orbit-service/src/subagents.rs)，库不直接管理 UI 或数据库连接。

Journal 批量和间隔由 `agent.rs` 的具名常量维护；UI 帧间隔属于 CLI，不与数据库刷盘间隔混用。

## 架构与核心组件

- **Agent 循环与规划器**：基于事件驱动模型，处理用户输入、驱动模型推理流、按模型返回顺序串行执行工具调用、收集工具执行结果并组装下一轮上下文。
- **后台命令协调**：会话内共享任务管理器，命令完成时在模型请求之间投递有限结果预览；显式等待已返回的结果不重复投递。无后续工具调用但仍有未完成命令时，通过事件暂停等待，不发起模型请求。运行取消、异常或被丢弃时取消所属任务，并以运行代次隔离迟到的结果。
- **子任务与消息边界**：宿主可注册独立的后台任务组，子 Agent 复用同一执行循环。运行中补充消息通过 `AgentInbox` 在模型请求前接收，与检查点及 `InputReceived` 事件一起提交；等待后台任务时，补充消息和进度提醒也可唤醒 Agent。进度提醒先写入执行检查点再交付模型，由父代理检查或沟通后决定继续/取消；宿主在父代理空闲时启动的续跑任务会在下一次父代理运行时接入。完成结果与原工具回执逐项提交，不生成第二条同 ID 的工具响应。
- **上下文预算估算**：实时追踪系统提示词、用户历史、工具定义与工具执行输出的 token 占用，确保在窗口溢出前主动触发整理。
- **分层整理与压缩系统**：结合静态工具输出精简、增量模型结构化摘要与数据库归档投影，实现无损或低损的上下文回收。
- **历史回读与证据审计**：通过由宿主注册的 `read_history` 工具，使模型能够在后续长任务中按需检索已被精简的原始历史证据。

## 上下文预算与分层整理

在每次发起模型请求前，Agent 均会严密核算上下文预算。`context_tokens` 代表模型声明的总窗口；若模型声明了独立的 `input_context_tokens`，则以此作为输入基准，输入预算按该独立窗口计算。

当估算输入占用达到输入预算阈值或用户显式执行 `/compact` 时，触发分层上下文压缩策略：

```text
当前上下文
  ↓ 输入预算占用达到 60%
[阶段 1: 工作集选择与归档]
  保留系统提示、最新用户要求及最新完整工具批次
  原始完整上下文事务性写入中央数据库独立归档
  ↓ 
[阶段 2: 工具输出精简 (Tool Pruning)]
  裁剪旧工具输出，仅保留首尾摘录、错误行与关键引用
  若占用降至目标预算且至少减少 25%，直接完成，不调用摘要模型
  ↓ 输入预算占用达到 85%
[阶段 3: 增量结构化模型摘要 (Summary)]
  以已有摘要为基础，将旧历史增量交由摘要模型总结
  记录来源指纹、结构化摘要与进度游标，支持后续断点续接
  ↓ 输入预算占用达到 92% 且满足回退条件的摘要失败
[阶段 4: 紧急归档投影 (Archive Projection)]
  使用归档引用与近期消息生成可回读投影，明确标记覆盖缺口
  保留可回读原文；若归档、摘要或最终预算校验失败，仍可能返回错误
```

### 整理关键设计约束

1. **工具配对不可分割**：任何压缩逻辑均以完整的 `Assistant { tool_calls }` 与对应 `Tool { tool_call_id }` 批次为最小单元，绝不为迎合预算而破坏调用配对协议。
2. **归档先行原则**：仅当原始完整上下文成功写入数据库归档后，才允许裁剪内存中的工具正文与大参数。
3. **分批自适应伸缩**：自动摘要从较小的 token 批次起步，平稳响应后逐步放大；遇到上游超时或截断时自动缩小批次，防止慢速模型单次耗尽时间。
4. **模型支持调整**：可通过 `compaction.model` 为摘要单独指定更轻量或更快速的辅助模型，减轻主模型负担。

## 原文回读与文件活动审计

### `read_history` 历史回读工具
- 不传参数时列出当前会话最新的归档 ID、创建时间与消息数量，每页最多 20 个；用 `next_before_archive` 作为 `before_archive` 继续查看更早的归档。尚未压缩时返回空列表与说明，不需要猜测 ID。
- 读取正文时使用列表或压缩记录中分配的 `archive_id`。
- 支持通过 `query` 关键词执行精确文本检索，或通过 `message`、`offset`、`length` 参数分页读取原始完整消息。
- 归档 ID 严格限制在当前会话内，切换或恢复会话时自动校验访问权限。历史记录仅作为证据溯源，不作为可重新执行的当前指令。

### 文件活动审计 (`FileActivity`)
- 记录成功的内置 `read_file`、`write_file`、`edit_file` 回执对应的文件活动：`read`（曾读取）与 `written`（曾成功写入）。
- 仅以工具实际执行回执为准，不采信模型在文本中声称的修改。多轮压缩与会话恢复时保持累计审计记录。

## 运行控制与流式体验

- **任务轮数与工具上限**：`max_turns` 默认 `0`（不限轮数），`max_tool_calls` 默认 `2000`（可在配置中按需调整，例如设为 75/500；对应值设为 `0` 表示不限制该项），防止 Agent 陷入无意义的死循环。
- **流式空闲超时**：流式模式下按“无数据到达间隔”进行空闲超时计时（默认 600 秒），持续的思考链或长文本输出不会因为总任务时长较长而被硬性截断。
- **协作硬中断与引导**：
  - 用户按下 `Ctrl+C` 触发硬中断：取消模型请求及支持取消的工具；已完成的消息、工具回执和执行检查点会持久化。未完成请求不会被当作成功回复，恢复时按检查点处理；宿主阻塞解析并不保证立即停止。
  - 用户在运行中输入补充要求并按回车：触发引导机制（Steerability），在当前请求边界安全重置，带着用户新补充的引导词发起下一轮规划。
- **输出截断处理**：当服务端返回 `max_tokens` 或 `length` 结束原因时，Agent 明确记录响应未完成，坚决不执行残缺的工具参数，防止解析异常。
